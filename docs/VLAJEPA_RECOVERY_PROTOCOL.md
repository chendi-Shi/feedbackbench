# VLA-JEPA 中断后恢复：重放观测、重算边界预测、继续闭环

本协议在恢复运行前冻结。原独立长任务在398个持久化控制步后因系统可用内存降到456,900,608字节而退出；进程RSS为5,648,232,448字节，低于6GiB自身上限。原目录 `outputs/frontier/vlajepa_long_horizon` 仍为未封存，全部源文件、57次已返回模型调用、398条执行记录及中止记录保持原样。本实验不重新封存原目录，也不把它改为未中断完成。

新目录为 `outputs/frontier/vlajepa_recovery`，入口为 `scripts/run_vlajepa_recovery.py`。研究问题是：能否在新进程中精确重建已保存的可观测执行前缀，重算最后一次完整预测并得到相同输出，再继续到官方成功或520步时限。它是一次**已有尝试的恢复验证**，不是新的独立评测样本，不与前三任务拼接成同协议4/4，不产生合并成功率。

## 固定模型、任务与资源

沿用[单长任务协议](VLAJEPA_LONG_HORIZON_PROTOCOL.md)的固定checkpoint、处理器、官方源码、环境资产、task1/init41/seed1000、360×360双相机、8维机器人观测、相对OSC、20Hz模拟控制、hard reset与10步settle、完整520步上限。模型仍为300个动态INT8 Linear、完整BF16分页embedding、其余推理与四步flow动作头FP32，每次七动作。没有训练、控制兜底、物体状态输入、改变种子或选择另一任务。

导入前和权重加载前系统可用内存至少5.75GiB；自身RSS上限6GiB；运行时系统可用内存下限0.5GiB，每秒采样，仅退出自身进程。不停止其他项目或系统服务，不增加云费用。新协议绑定原长任务22个冻结源以及本runner、本协议、`scripts/audit_vlajepa_interrupted.py`前缀审计，共25个源；同时绑定所有用于恢复的原始文件哈希。模型在一个新进程中只加载一次。

## 恢复边界与必须成立的检查

1. 新环境以相同种子和初态reset。核验初始机器人观测与双相机，再重放原始第1至392步动作；每步核对保存的8维机器人观测、双相机像素哈希、终止标志和官方成功标志，必须逐值相同。没有保存原环境完整qpos/qvel等内部状态，因此不能把该检查称为完整物理内部状态一致。
2. 第392步结束后，核验与原`call_0056`相同的当前输入。该调用的NPZ保存的是forward之前的CPU RNG状态，没有after状态。恢复这个before状态，并**实际重新执行一次完整模型forward**；核验输入、RNG、初始噪声、模型动作及环境动作与原记录逐值一致，确认300量化模块实际执行、四次动作头求值。不得把before状态当after，也不通过假定随机数消耗来推导after。
3. 继续使用这次真实forward自然产生的RNG状态。执行七动作块中的前六个动作，逐步与原第393至398步相同的观测、像素哈希和终止标志核对。第399步执行剩余的第七个动作；之后每七步以最新观察真实调用模型，直到官方成功或原520步时限。
4. 任一精确检查、容量或警告检查不通过就保留错误并停止，不放宽容差、不改种子、不跳过比较。上游reset可能吞掉持续warning异常的已知限制仍保留；无进展须退出自身运行并保存中止，不能据此声称已保证立即失败。

固定策略的公开predict_action_chunk路径没有跨调用ACTION队列或KV缓存复用；仍以实际重算的边界输出一致作为继续的必要条件，不用静态推断代替验证。该协议未把完整历史内部模型状态视为已记录。

## 证据与计数

逐项区分：392个纯保存动作重放步；6个边界重算后、与旧轨迹重叠的核对步；第399步起的新执行；1次边界模型重算；边界之后的真实新模型调用。原来的57次模型调用保留为原历史证据，重算调用是额外执行，不增加独立机器人样本数。若未提前成功，逻辑轨迹最多520步，不能用重放步数宣称新模型全程重新预测。

保存恢复前缀比对、逐步动作/机器人观测/双相机哈希、arena初始化和逐步容量与警告、每个真实新调用的RNG/噪声/前后处理动作/模块覆盖/NFE，以及最终结果、图像和录像。录像和报告必须明确标注前392步使用保存动作重放，不能把它呈现为一次全新、未中断的520步策略运行。加载、重放、边界重算、新推理与总墙钟分开记录；不将重放开销省略后当作端到端推理速度。

只有所有来源和前缀核验通过、后续到达官方成功或完整时限，并生成独立恢复封存凭据、通过严格validate，才计为恢复完成。任务成功由官方谓词决定；走满时限未成功是任务失败；资源保护、异常、缺失或未封存都不是完成的任务失败。原长任务的未封存状态始终不变，报告按原阶段和恢复阶段分别列出。

新结果只能支持这个已知初态的一次恢复可行性；不能证明完整LIBERO性能、量化无损、原生BF16等价、未见任务泛化、稳定内存最低要求或真实机器人实时控制。禁止在同一目录自动覆盖重试；所有失败与中止必须继续保留。
