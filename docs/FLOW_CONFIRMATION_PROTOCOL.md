# SmolVLA 完整时间区间两步采样：前瞻确认协议

本阶段在 **2026-10-15**、看到新初态结果之前固定协议。目标是在单机 CPU、零云费用约束下，检验此前探索性发现是否能在新的本项目初态划分上重复。权威执行定义为 [新 runner](../scripts/run_flow_confirmation.py) 和运行前生成的 `outputs/frontier/flow_confirmation/protocol.json`；结果只能写入新的阶段目录，不能覆盖 v1。

## 为什么做这个试验

[v1 完整结果](RESULTS.md)中，noise2 在共同 init11 的四个任务上成功4/4，full10也是4/4，而两种缓存方法均为3/4。这四例用于提出本阶段假设，属于探索性证据；它们不能重新包装成预先选择 noise2 的确认结果。

本阶段只比较 **当前观测条件下从新噪声覆盖整个 flow 时间区间的2步与10步采样**。它没有动作缓存、检索门槛、动作重混合或额外质量门控。没有新算法首创或前沿基础模型训练声明；研究贡献在于可复核的前瞻验证、闭环预算和结果的同时评估。

## 固定任务、初态与分母

| 项目 | 预声明定义 |
|---|---|
| 模型 | 与 v1 相同的公开 SmolVLA 检查点及文件 SHA，CPU / float32 |
| 任务 | libero_spatial、libero_object、libero_goal、libero_10，各 task_id=1 |
| 新初态 | 每个任务 init_state_id=41、43 |
| 方法 | full10、noise2 |
| 计划规模 | 4任务 × 2初态 × 2方法 = **16回合** |
| 比较单位 | 每方法8回合，共8组配对，嵌套于 **4个任务簇** |
| 排除的旧数据 | v1 init1开发、init11/29评估以及旧 MINERVA 回合都不并入本阶段分母 |

初步讨论中的 init53 经官方资源检查发现越界：四个任务的对应初态档案均只有50个状态。因此在任何新试验之前固定为41/43，并记录初态档案哈希与数量。不能运行时轮转、取模、改成其它成功率更高的初态或静默补选。

这些任务与初态来自公开 LIBERO；“新初态”仅指未用于本项目 v1，不证明上游预训练没有见过这些状态、任务或相似轨迹，也不是未见任务泛化试验。

## 两个采样条件与执行环境

full10 从原始噪声沿完整 `[1,0]` 区间走10步 Euler 网格；noise2 从同样配对噪声沿完整区间走2步粗网格。noise2 不是在 `t=.2` 开始的缓存细化，不读取开发 latent。两者都执行当前观测的 VLM。

两种方法每次产生50动作，只执行前10动作后重规划，关闭时间集成。图像360，CPU2线程、interop1线程，配对 seed=1000，保持同一模型、预处理、动作后处理、环境与调度参数。每个方法在同一决策序号生成同一形状的噪声，保存噪声 SHA；轨迹分化后的输入不要求相同。

每个进程有预先定义的模型 warmup，不计为评估回合。方法顺序由 runner 在执行前固定并平衡，不根据中途结果调整。每回合运行到官方成功终止或完整上限：spatial/object各280步，goal300步，libero_10为520步。失败、异常和未完成的尝试必须保留；不能用提前截断来降低失败耗时。

## 预声明问题与统计口径

主要对比方向固定为 **noise2 − full10**，同时报告以下不同维度：

1. 官方成功标志与逐回合结果；任务等权配对成功差。
2. 每调用 action-head NFE、全部回合的调用数和总 NFE。NFE不包含VLM成本，不能等同端到端加速。
3. 每回合平均调用耗时的配对差；调用池p50/p95另作描述，不能混用权重。
4. 双方成功配对中的回合 wall 差，只是按结果条件化的描述量，不给置信区间，不报告总体加速倍数。全部回合原始wall仍公开。

先求每个任务内两个初态的配对差，再对四个任务等权平均。置信区间采用 **2,000次任务簇 percentile bootstrap，seed=20261015**。只有四个任务簇，区间不稳定；成功差区间包含0或退化为零宽，均不构成等价、非劣或真实不确定性为0的证据。不能把8个初态配对、16个回合或数百次调用当作独立任务。

首10步动作差仅作诊断：比较后处理后、环境内部限幅前的7维命令，按通道保留RMSE/MAE与最大差。七维混合坐标RMSE不是质量指标，也不是整个50动作块误差。任一回合不足10步就把该诊断标为缺失，仍保留其成功/失败结果；不得改成短前缀并沿用“首10步”标签。

## 完整性与导出

runner冻结新协议、旧研究来源绑定、必要源码、模型和环境资源身份。每回合保留attempt、完整结果、调用日志、轨迹、初始/最终图像及视频，并以receipt封存。配对校验初始正面/手腕图像、机器人状态、环境/调度配置和共有决策序号的噪声SHA。验证原始证据时不启动模型或模拟器。

[新报告器](../scripts/summarize_flow_confirmation.py)默认拒绝未完成阶段；只有显式 `--partial` 才可生成部分报告，且保留全部16个计划回合、缺失/未封存/错误状态和8个计划配对，不补成功率。完整结论只能依据全部16个回合。

报告导出 `report.json`、`report.md`、`groups.csv`、`episodes.csv`、`pairs.csv`、`calls.csv`，以及两张PNG/SVG图。`exports.json` 在所有导出完成后最后写入，绑定固定文件列表及SHA。`validate_report` 只读核对原始证据、实现SHA、输出哈希，再重新计算统计、Markdown和CSV。报告代码本身的SHA独立记录，不能用更新报告代码来改写冻结执行定义。

共享本机负载会影响计时。同步仿真在推理时暂停，因此20Hz控制周期不意味着CPU实时推理能力。本阶段不支持完整LIBERO、SOTA、真机效果或广泛任务泛化声明；即使结果为负，也完成既定范围并保留。
