# FeedbackBench：方法迁移、前瞻验证与求职展示

当前有两条相连的工作线：**将2026年ActionCache机制迁移到SmolVLA并做前瞻确认；将固定VLA-JEPA检查点接入这台电脑上的真实机器人仿真闭环，验证受限资源下的执行与证据完整性。** 项目仅使用一台约16GB、无CUDA的Windows电脑，零云费用。研究对象是推理方法与实验系统；没有训练基础模型，也不把既有SmolVLA称为2026 SOTA。

**VLA-JEPA闭环进展：2026-10-16，三个已知任务在compact和逐任务独立进程两个阶段均真实执行并封存成功。** 每阶段分别为109、128、90步，共327个执行动作、48次完整模型调用、192次动作头求值。只读对照两阶段的动作、机器人状态及48次调用的输入哈希、RNG、噪声和前后处理动作，均逐值相同；这是相同任务/初态的重复执行证据，不是六个不同任务。两个四回合设计的第四项均因资源保护未完成。独立6GiB预算的长任务随后保存57次完整调用和398步动作，因系统可用内存0.426GiB低于0.5GiB下限中止，仍为0完成、1未封存，不计任务失败。见[compact结果](VLAJEPA_COMPACT_RESULTS.md)、[独立进程结果](VLAJEPA_ISOLATED_RESULTS.md)、[长任务结果](VLAJEPA_LONG_HORIZON_RESULTS.md)与[分协议任务证据索引](../artifacts/vlajepa-task-coverage-20261016.json)。中断后的恢复入口已正式尝试，但最新重试时0.348GiB可用内存低于5.75GiB冻结门槛，未加载模型或执行动作；恢复仍未完成，见[恢复结果页](VLAJEPA_RECOVERY_RESULTS.md)。

**前瞻确认：2026-10-15，16/16回合封存，0运行错误、0缺失。** 固定初态41/43，4任务簇、8配对；full10成功 **4/8**、noise2 **5/8**，成功差 **+12.5pp [0,37.5]**。总action-head NFE由 **2050降至370（−81.95%）**，调用由205降至185；每回合平均调用耗时的任务等权差为 **−5.253s [−10.743,−1.225]**。成功差只来自object/init41；两个长程初态双方均失败，不能宣称普遍优越、非劣或稳定部署提速。见[后续结果](CONTINUATION_RESULTS.md)、[完整报告](../outputs/frontier/flow_confirmation/report.md)。

**v1：2026-10-14，28/28回合封存，0运行错误、0缺失。** 开发4回合，3成功、1失败；仅成功回合准入，cache2/cache0各冻结30条记录。24个held-out回合全部完成：主比较full10 **7/8**、cache2 **6/8**，成功率差 **−12.5pp [−37.5,0]**；init11消融full10/noise2各4/4、cache2/cache0各3/4。数据没有支持缓存保持成功率并稳定加速。见[v1研究结果](RESULTS.md)、[完整report.md](../outputs/frontier/cache_study/report.md) / [report.json](../outputs/frontier/cache_study/report.json)。

## 主比较、消融与方法差异

| 面板 | 结构 | 正确分母 |
|---|---|---|
| 开发/prefill | 四个suite各task1，init1，full10 | 4回合；仅用于缓存准入，不是测试成绩 |
| 主比较 | 四任务，各init11、29，full10对cache2 | **8组配对、每方法8回合、4个任务簇** |
| 探索消融 | 同四任务，仅init11，full10/noise2/cache2/cache0 | **每项对照4组配对、每方法4回合**；full10/cache2与主比较重叠 |
| 总执行计划 | 开发4 + 主比较16 + 补充条件8 | **28回合**；不是28个独立任务，不能再次累加消融面板 |
| 独立前瞻确认 | 同四任务，新的init41/43，full10对noise2 | **另16回合，8对、4任务簇**；不与v1合并成功率 |

阈值**0.95**、投影维度**500**、密度**0.01**、容量**3000**在rollout前固定，未按此次结果调优。缓存仅覆盖三个成功开发任务的30个采样记录；`libero_10`的开发失败没有准入，但全局检索不按task ID路由，仍可能跨任务命中。这种覆盖不平衡是解释边界，不通过事后补选成功初态消除。

所有条件计算当前VLM，每10控制步重规划，关闭时间集成。full10从噪声走10步；noise2从同一噪声走覆盖完整区间的2步粗网格；cache2命中才从原生t=.2的中间latent续算原网格最后2步；cache0命中才使用独立t=0最终动作缓存。两个缓存条件miss均回退full10。

cache2对noise2用于观察检索细化与单纯减步的区别，但两者miss预算不同，不能称为严格等NFE对照。这里是**ActionCache-inspired offline frozen cache**：只从成功开发回合离线建造，测试不更新、不淘汰；与原论文在线成功回合缓存管理及LRU不同。它换取清晰的数据隔离，也限制新状态适应能力，结果不能代替原论文在其它模型和硬件上的结论。

前瞻确认只比较full10与noise2，没有缓存检索。运行至成功终止或冻结上限：spatial/object/goal/LIBERO-10分别 **280/280/300/520步**。它覆盖四个suite各task1，不能称完整官方benchmark；init41/43只是本项目新初态，未证明从上游预训练中排除。原MINERVA已完成的 **232回合**、v1的 **28回合**、前瞻的 **16回合**分别报告；原计划未尝试的12+4回合没有因新实验同为16回合而变成完成。

## 负结果如何回答

**“没有加速或成功下降，项目还有什么贡献？”** 可以回答：交付的是可审计的方法迁移和检验，是否值得采用由数据决定。真实上游parity排除了关键采样错误来源；固定划分、miss回退和完整调用计时使结果能被独立检查。工程完成不能等同于研究假设成立。

实际结果中可展示以下差异，不能合成一个speedup数字：

- **零命中：** 固定0.95阈值、当前特征/开发覆盖下，缓存没有节省NFE。不能宣称检索有效，也不能测试后降阈值仍沿用原协议。
- **有命中、NFE降低但成功下降：** 观察到计算与质量代价，未支持成功保持；失败回合较短不算有效加速。
- **NFE降低但完整耗时未稳定下降：** 按VLM/检索/动作头分项讨论瓶颈；不能只展示动作头成本。
- **观察成功相同且成本降低：** 报告这组配对样本与区间，4任务簇仍不足以证明普遍等价、非劣或泛化。

本轮主比较cache2命中 **23/163（14.11%）**，每调用NFE从10降至8.871；调用数却从145增至163，整组总NFE从1450降至1446，仅降 **0.28%**。Spatial/init11中cache2在6次命中后仍失败，总NFE232，相对成功full10的100为2.32倍。LIBERO-10的cache2在两个初态共77次查询均未命中；成功的init11是完整回退，不能写成缓存带来的成功。已观察到的命中均来自同任务开发记录，每回合无连续重复同一缓存索引；这不证明缓存动作适合当前状态。详见[失败案例FA-004](FAILURE_ANALYSIS.md)及[检索记录](../outputs/frontier/cache_study/retrieval_analysis.csv)。

旧MINERVA已有负结果：clean主比较adaptive **15/16**、fixed8 **16/16**，成功率差**−6.25pp**，任务簇区间**[−18.75,0]**，平均调用增加**93.1%**。可展示如何保留失败并承认启发式没有改善预算权衡；不能用旧模型结果预判新缓存机制。
