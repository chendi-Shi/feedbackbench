# VLA-JEPA INT8：四任务闭环可行性协议

这是在首个闭环回合前固定的小规模接入诊断。问题是：已经通过单观测前向的动态 INT8 VLA-JEPA，能否在真实 LIBERO 仿真中持续读取当前图像、语言和机器人状态，生成并执行动作，直到官方成功或完整时限？结果同时报告任务成功和运行错误；完成运行不等于完成任务。

固定官方 LeRobot 端口与 `lerobot/VLA-JEPA-LIBERO` 检查点，复用已经审计的逐层量化加载器。Qwen 的 300 个 Linear 为动态 INT8，共享 token embedding 以 BF16 存储、输出 FP32，其他 Qwen 参数和完整动作头为 FP32。保留官方四步 flow、七步动作块和原始动作后处理；没有训练或更新权重。

| 条件 | 运行前固定值 |
|---|---|
| 任务 | libero_spatial / libero_object / libero_goal / libero_10，各 task_id=1 |
| 初态 | 每任务 init_state_id=41，共 4 回合，按上表顺序执行 |
| 随机种子 | 每回合 1000；保存调用前 CPU RNG 状态及动作头实际抽取的初始噪声 |
| 时限 | 280 / 280 / 300 / 520 控制步；仅官方成功可提前结束 |
| 控制 | 相对 OSC，20 Hz 仿真控制，reset 后官方 10 步 settle；推理时物理仿真暂停 |
| 观察 | 当前主相机、腕部相机、8 维机器人自身状态及真实任务文本；不向策略暴露物体状态或成功标签 |
| 图像 | 环境输出 360×360；适配器翻转高宽一次，官方模型按固定配置缩放到 224×224 |
| 重规划 | 每次生成 7 个动作并顺序执行，队列耗尽后读取最新观察；无时间集成、缓存检索或失败兜底 |
| 预算 | CPU 两个计算线程、一个 inter-op 线程；一次仅加载此模型和一个环境；不使用云服务 |
| 内存保护 | 导入前及权重物化前可用内存至少 5 GiB；运行时自身 RSS 上限 5.5 GiB、系统可用内存下限 0.5 GiB，每秒采样；只允许退出自身进程 |
| 预热 | 无额外预热；首个调用计入本回合，加载时间单列，不将计时称作稳定吞吐 |

这四个初态曾用于 SmolVLA 研究，选择它们是为了明确接入范围，不是新的 held-out 质量集。模型、数值实现、动作块长度和运行时不同，不能把结果和既有 SmolVLA 结果直接做方法增益或量化损失比较。只有四个任务各一个初态，不做显著性、非劣、泛化或完整基准成绩声明。

运行前封存本协议、runner、量化加载器、原生加载辅助、仿真与执行器源码哈希、模型/处理器/官方源码 manifest、仿真资产身份及已发布初态身份。模型与实际环境模块必须均来自指定 frontier LeRobot 源树，Windows 平台兼容仍使用已有审计路径。

每次规划保存前后处理动作块、实际初始噪声、调用前 RNG 状态、输入指纹、实际量化模块覆盖、动作头求值次数与计时。每回合保存全部执行动作、机器人状态、重规划索引、逐步耗时、初始双相机和最终图像、录像、结果及逐文件 SHA 封存凭据。后处理后的夹爪动作应为 -1/+1，不再额外反转或裁剪。观察变化后的后续动作来自新推理。

已完成且封存的回合可只读核验并跳过；部分、错误或内存中止的回合保留，不自动覆盖重跑。内存不足时先于模型加载退出并保存状态；之后可在同一冻结协议下继续尚未开始的回合。中途保护退出不算任务失败，也不能从计划分母中删除。

报告分别列出计划 4 回合、已完成、成功、官方失败、运行错误/缺失，以及每个任务的步数、规划次数、动作头 NFE、延迟分布和内存采样。原有 MINERVA 232、ActionCache 28、少步确认 16 回合与本诊断分开统计。即使闭环成功，也不能据此声称与原生 BF16 等价、真机可用或实时控制。
