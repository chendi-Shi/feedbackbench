# VLA-JEPA 分页 embedding：本机低内存可行性协议

本协议在新变体首次真实前向和闭环回合前固定。研究问题是：在保持已有动态 INT8 模型数值路径的前提下，把共享 BF16 token embedding 从完整 owned 内存改成文件映射，能否减少本机常驻内存，并完成四个真实 LIBERO 回合？先验证单个已保存观察的动作一致性，再执行闭环；单观测通过不等于闭环通过。

这是独立工程变体，标识为 `cpu_qwen_dynamic_int8_paged_bf16_embedding_fp32_action`，case model 为 `vlajepa_paged`。入口为 `scripts/run_vlajepa_paged.py`，提供 `probe`、`freeze`、`run`、`report`、`validate` 子命令；映射辅助为 `scripts/vlajepa_paged_embedding.py`。闭环证据使用独立的 `outputs/frontier/vlajepa_paged_closed_loop` 目录。原 `outputs/frontier/vlajepa_closed_loop` 的 5 GiB 协议、冻结源码、阻断记录和报告保持不变。新变体即使完成，也不表示原 5 GiB 阶段完成；两者不得合并统计或相互补足缺失回合。

## 数值与存储约束

固定已有官方 LeRobot 端口、`lerobot/VLA-JEPA-LIBERO` 检查点、序列化处理器及输入 manifest。Qwen 的 300 个 Linear 继续逐层动态 INT8 量化，外部输入输出为 CPU FP32；其他 Qwen 参数和完整动作头仍为 FP32。保留官方四步 flow、七步动作块和原始后处理，没有训练、更新权重、低秩替换或动作兜底。

唯一预期存储改变是共享 token embedding：形状 `151936 × 2048`、BF16、622,329,856 字节，以 `mmap.ACCESS_COPY` 私有写时复制映射承载。映射按系统 allocation granularity 对齐，张量使用精确文件偏移；保留原 embedding 模块、BF16 weight 和 lookup 输出转 FP32 的 hook。`lm_head.weight` 必须引用同一个 Parameter。官方动作路径调用内部 Qwen 模型，跳过词表 logits；不得额外调用 lm_head、全表转 FP32、clone 或以初始化数据替代检查点值。

读取前核对文件身份、边界、dtype 和 shape，分块检查全部源值有限，并核对原生 tied embedding 两份存储字节相等。有限性检查不能留下运行时已触页的整表映射：可用分块读取，或检查完关闭独立映射后重新建立运行时映射。映射生命周期覆盖模型生命周期；不得提前关闭仍被 tensor 引用的 buffer。映射辅助不得消耗 Torch RNG。实际加载审计必须记录分页模式、shape、dtype、字节数、源身份与偏移、有限性检查及共享引用检查；只改 variant 名字而继续 owned 加载不满足本协议。

模型理论参数 payload 仍为 **3,072,709,660 字节**。减去 embedding 后其余 payload 约 2.282 GiB，不代表进程 RSS 上界。分页可能减少私有驻留页，但仍占虚拟地址空间，访问过的文件页可进入工作集或系统缓存。只能报告实测内存，不能预先宣称一定节约 0.580 GiB 或压缩了模型参数。

## 独立探索性资源预算

导入前和权重物化前，系统可用内存均须至少 **3.5 GiB**；运行时自身 RSS 上限 **5.5 GiB**，系统可用内存下限 **0.5 GiB**，每秒采样。保护只能退出自身进程，不停止或调整其他项目、常驻应用及系统服务，不使用云算力。

3.5 GiB 是此新变体预先声明的探索性启动预算，允许尝试失败，不是官方最低配置，也不是已证实的安全上界。依据是去掉完整 owned embedding 后的参数量，以及原加载器最大单层 FP32 权重为 64 MiB；packed kernel 元数据与复制、allocator、图像处理、激活、模拟器及共享主机波动仍需实测。原单前向成功时加载前约有 5.846 GiB 可用内存，不能用它证明 3.5 GiB 已经足够。每秒采样也不能保证捕捉瞬时峰值或防止所有内存错误。

加载、推理和模拟运行均保留内存保护及阶段记录。预算不足应在权重加载前退出并记录 `blocked_preflight`；加载或推理过程中触发保护、异常或未完成则保留实际状态和已有证据，返回非零，不记为任务失败。后续若必须改变阈值、存储实现或任务配置，应形成新的显式协议版本并保留本次结果，不能在已冻结协议中静默放宽门槛。

## 单观测验证门槛

先运行 `probe`，使用与已有成功 INT8 probe 相同的保存观察、输入 SHA、官方源码/检查点/处理器、CPU 两个计算线程、一个 inter-op 线程和量化引擎，采用原构造顺序及 `torch.manual_seed(123)`。以保存的原 INT8 probe 输出为对照，不同时加载两个大模型。原对照及新源文件的身份均写入新 probe 记录；不得覆盖原 probe。

新输出必须是有限 FP32 `(1, 7, 7)`，300 个量化 Linear 都实际执行，完整官方四步动作头执行；前后处理动作均保存。逐值比较原 `model_actions` 和 `environment_actions`，要求 `array_equal`，并报告差异数量与最大绝对误差。若不一致，保留新输出及失败记录，先解释差异，不能改容忍阈值后宣布通过。此检查仅支持该观察下两种存储路径动作一致，不证明对所有输入等价，也不证明与原生 BF16 模型等价。

只有真实单观测前向、加载审计和一致性检查通过后，才进入闭环。probe 是接入验证，不计入四回合，也不是独立泛化测试或任务成功成绩。

## 四回合闭环固定设计

| 条件 | 运行前固定值 |
|---|---|
| 顺序与任务 | libero_spatial / libero_object / libero_goal / libero_10，各 task_id=1 |
| 初态 | 每任务 init_state_id=41，共 4 回合 |
| 随机种子 | 每回合 1000；保存调用前 CPU RNG 状态和动作头实际初始噪声 |
| 时限 | 280 / 280 / 300 / 520 控制步；只有官方成功可提前结束 |
| 控制 | 相对 OSC，20 Hz 仿真控制，reset 后官方 10 步 settle；推理时仿真暂停 |
| 观察 | 最新主相机、腕部相机、8 维机器人自身状态及真实任务文本；不向策略提供物体状态或成功标签 |
| 图像 | 环境 360×360；适配器高宽翻转一次，官方固定配置缩放到 224×224 |
| 重规划 | 每块 7 个动作顺序执行，耗尽后读取最新观察；无时间集成、缓存检索或额外动作变换 |
| 执行 | CPU 两个计算线程、一个 inter-op 线程；一次一个模型和一个环境；无云服务 |
| 预热 | 无额外预热；首调用计入回合，模型加载时间单列 |

这四个已知任务的初态曾用于 SmolVLA 研究；沿用它们用于明确接入范围，不是新 held-out 集。不得把不同 checkpoint、数值实现、动作间隔和运行时的成绩解释为与 SmolVLA 的方法增益、量化质量对照或完整 LIBERO 基准成绩。仅四个回合不做显著性、非劣性、泛化、真机或实时控制声明。

## 冻结、证据与失败处理

闭环开始前冻结本协议、新入口、映射辅助、原闭环 runner、原逐层量化及 native helper、原执行/仿真相关全部源文件的 SHA，模型/处理器/官方源码 manifest、依赖版本、仿真资产、已发布初态身份，以及通过门槛的 probe 身份。新协议 source inventory 不能只含 wrapper，必须覆盖所有实际依赖。执行与校验必须拒绝原协议目录及不匹配的 source/configuration；模型和环境模块仍均来自指定 frontier LeRobot 源树。

保留原闭环严格证据契约：每次规划保存前后处理动作块、实际噪声、调用前 RNG、输入指纹、300 个量化模块覆盖、动作头求值次数和耗时；每回合保存逐步执行动作、机器人状态、下一观察指纹、重规划索引、逐步计时、初始双相机和最终图像、录像、结果及逐文件 SHA 封存凭据。后处理夹爪仅为 -1/+1，不再反转或裁剪。加载审计在原完整消费、有限值、无 meta 参数、量化库存和共享权重检查之外，还必须通过分页专属检查。

完成且封存的回合允许只读核验后跳过。尚未创建的回合可在同一冻结协议下继续。部分回合、异常、内存保护中止、未封存记录及失败 probe 均保留，不自动覆盖重跑、不删除失败、不用不断更换目录筛选成功。入口资源阻断且未执行动作，不是任务失败；完整跑到官方时限但未成功，才是任务失败。旧 owned 变体记录不搬入新目录，不补作新回合。

`report` 分列计划 4、完成、成功、官方任务失败、运行错误、未封存和缺失，并列各任务步数、规划次数、动作头 NFE、延迟和内存采样；共享主机计时不称稳定吞吐。严格 `validate` 只有四回合全部封存、来源和逐步证据一致时才确认完成，不能把部分报告当作成功退出的完成证明。MINERVA 232、缓存研究 28、少步确认 16、旧 owned VLA-JEPA 阶段、新 probe 与本分页闭环分别统计。

实现语义参考 [Python mmap](https://docs.python.org/3/library/mmap.html) 的私有写时复制与偏移对齐约束，以及 [PyTorch torch.frombuffer](https://docs.pytorch.org/docs/stable/generated/torch.frombuffer.html) 的共享存储接口；实际依赖版本以本项目冻结记录为准。
