# VLA-JEPA 长程任务：独立 6 GiB 资源预算验证

本单任务协议在执行前冻结。此前单进程 compact 阶段前三任务成功、第四个初始化时自身 RSS 超过 5.5 GiB；每回合独立进程的阶段再次完成前三任务，但第四个在首次推理尚未返回、未执行预测动作时，RSS 达 **5,908,762,624 字节**，比 5.5 GiB 上限高 **3,182,592 字节**。当时系统可用 **889,200,640 字节（约 0.828 GiB）**，未触及 0.5 GiB 保护。这否定了“仅隔离进程已足够”的预期；不能把该阶段称为完整四回合成功。

本次只验证尚缺完整结果的 `libero_10` task 1、init state 41、seed 1000，在明确增加自身 RSS 预算后能否完成。新的入口为 `scripts/run_vlajepa_long_horizon.py`，独立输出 `outputs/frontier/vlajepa_long_horizon`，case model `vlajepa_long_horizon`。**计划恰好 1 个回合**，不移动、复制或重新封存此前三个成功结果；所有原始中止记录完整保留。新单任务若完成，只能写成该阶段 1 回合完成，不能把前三项拼成同一协议的 4/4。

## 固定参数与改变范围

唯一实验性配置变化是资源预算：进程启动与权重加载前，系统可用内存必须至少 **5.75 GiB**；进程自身 RSS 上限 **6.0 GiB**；运行时系统可用内存下限仍为 **0.5 GiB**，每秒采样。5.75 GiB 是基于此前实测后声明的探索性入口门槛，不是已证明最低配置。6.0 GiB 是本次允许尝试的上限，也不是宣称实际需要或一定够用的内存量。不得在本次执行后继续原地调高阈值；若失败则保留结果。

沿用 [compact 协议](VLAJEPA_COMPACT_PROTOCOL.md) 的所有数值、物理和控制参数：官方固定 checkpoint 与处理器、300 个动态 INT8 Linear、完整 BF16 分页 embedding 与共享引用、FP32 动作头、4 步 flow、每块 7 个动作；256 MiB arena、nconmax=5000，其他场景和渲染属性不改。完整 360×360 双相机、8 维机器人自身状态与任务文本输入，20 Hz 相对 OSC、hard reset 和 10 步 settle；最多 **520 控制步**，官方成功条件可提前结束。两个 CPU 计算线程、一个 inter-op 线程，没有预热、训练、控制兜底、物体状态输入或云服务。

使用一个新的独立 Python 进程，重新构造并加载同一模型；执行前仍核验单观测模型动作一致性及四套件 978 步环境重放证据。冻结原 compact 的 20 个源及本入口、本协议，共 **22 个源文件**，并绑定模型、官方源码、仿真资产、初态及处理器来源。改变资源门槛不等于改变模型精度或输入，不以任务结果选择新种子、初态或动作策略。

## 执行、失败和证据

继承逐规划 RNG、实际初始噪声、模型/环境动作、当前输入指纹、300 模块实际覆盖及 4 次动作头调用；保存逐步执行动作、机器人状态、最新观察指纹、图像、录像、轨迹、结果与逐文件 SHA receipt。继承 arena 初始化编译审计和 reset/每步警告与容量检查。结果及 progress 的计划数必须明确为 1；原四回合 runner 的通用执行内核不决定本阶段分母。

JSON 写入及 receipt 封存使用有界 PermissionError 重试，不重试动作或模型推理。已完成回合只读核验；未开始且仅 preflight 阻断可保留记录后续跑；部分、异常和未封存回合不自动覆盖重跑。资源保护仅退出本实验进程，不停止或调整任何其他项目。底层 reset 可能吞掉持续 warning 异常的已知上游限制仍保留，不宣称已修复；无进展时必须保留记录并终止本实验，不能跳过警告封存。

只有本回合达到官方成功或完整 520 步时限、封存并通过严格 `validate`，才确认本阶段执行完成。到时限未成功是任务失败；预算不足、首次推理未返回、异常或未封存不是任务失败。报告实际步数、成功谓词、规划次数与 NFE、加载开销、推理和回合耗时、每秒采样峰值 RSS 与最低系统可用内存；不把加载时间隐藏进性能表述，也不预设任务一定成功。

本任务是资源限制后的针对性可行性验证，属于已知初态，不能估计整体 LIBERO 成功率、量化损失、泛化或稳定实时能力。可以按任务列出各独立阶段实际已有的闭环证据及各自预算，但必须同时列出之前两次四回合阶段未完成的事实，不能将它们改写成同一冻结协议全部通过。
